# G2 2.3.0.24 CFW draft rebase (2.2.10.10 → 2.3.0.24)

**Status: DRAFT — UNVALIDATED — NOT FLASHABLE.** This advances the g2flash CFW
rebase onto stock **G2 2.3.0.24** as far as byte-level verification allows. It is
not a finished changeset: two ABI-sensitive seams and a set of RAM globals remain
unresolved, and nothing here has had the independent ABI/control-flow review or the
hardware test that AGENTS.md and the existing `2.3.0-cfw-compatibility.md` audit
require before any build or flash.

Stock 2.3.0.24 is a real, authenticated Even release (both firmware-check endpoints
return G2 2.3.0.24 / R1 2.3.0.0005; image sha256
`187ccf2bcc5c17a212106e8a376745511e8289c4232b634a7ea94b9bf25a0979`, DELTA `0x379bf5`,
main payload +44,836 bytes vs 2.2.10.10). Codec, BLE-controller, touch and case
components are byte-unchanged; bootloader and Apollo main changed.

## Method and verification bar

Every accepted relocation was verified, not merely proposed:
- code addresses by **unique normalized Thumb instruction windows** (24/16/10 tokens,
  four alignments) confirmed against the 2.3.0 stock bytes;
- **bl-target consistency** — for every relocated `bl` site the callee must itself map
  consistently. This caught a *wrong* unique-window candidate for `COMPASS_REPORT_BL_SITE`
  (its window match failed bl-consistency; the correct site was found by callee-mapping);
- restructured `bl` sites by **mapping the stock callee** and matching the call-site
  ordinal (identical call-site counts in both images);
- data tables by **exact content match** (`BLE_FAST_INTERVAL`) and by **registry-row +
  callback-consistency** (`AUDM_PEER_SYNC`: the 2.2.10 cb `0x56b1f6` maps to `0x56e6ea`,
  which is exactly the cb in the `0x010C` row found at `0x6c6268`).

## Blockers to a buildable candidate

1. **`IDLE_INPUT_GATE` is a semantic blocker, not a relocation.** In 2.2.10 the idle-input
   path does `ldr r4,[r0,#8]; bl 0x45ea68; cmp r0,#1` and the CFW replaces that `bl` with
   `faceclaw_idle_input_gate` to gate idle taps under the Faceclaw lease. In 2.3.0 the accessor
   call was **inlined** — `ldr r0,[r1,#8]; ldr r1,[r0,#4]; cmp r1,#1` — so there is **no `bl` to
   redirect**. This needs a decision: **(a) redesign the hook** onto the inlined sequence (a new
   patch site + its own ABI review), or **(b) drop the idle-tap gating feature** for 2.3.0
   (the CFW builds without it; Glanceboard idle taps would not be lease-gated). This is the one
   thing standing between the current map and a complete patch set.
2. **Three indirectly-called rom-calls** (`0x47d429` fast-link, `0x4ba0b7`, `0x47eaa5`) are
   reached via `blx`/function pointers, not direct `bl`, so they need blx-site or
   adjacent-function mapping — finishable, low risk.

## Gates that remain regardless

- **ABI / register-and-stack contract review** of every relocated hook (the gesture handlers,
  wear, compass, display-copy) — a matched address does not prove a matched calling convention.
- **On-device hardware test** on glasses that can still receive an OTA if the image boot-loops.

`cfwBuildAllowed` stays **false** until 1–2 and both gates are cleared. This draft is a
verified, near-complete starting point — not a finished or flashable changeset.
